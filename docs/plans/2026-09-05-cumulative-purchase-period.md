# 累计套餐按最近一次成功发放统计

修正 87730c6 将同一 subscription_id 的历次购买累计计入总额度的问题。同一用户同一分组续购沿用原订阅 ID，因此订阅 ID 不是独立购买周期。原生 monthly_usage_usd 也是月窗口统计，不能作为累计套餐的本次用量。

## 统计与限额

当前统计起点取同一用户、同一分组最近一个成功发放的订阅订单时间，与 subscription.starts_at 中较晚者。失败订单、流量包、其他用户/分组及未来发放不改变周期。没有成功支付订单的人工分配订阅以 starts_at 为起点。结束边界保留现有 expires_at，不推算或改写现有有效期。

只统计该订阅该用户在 `[period_start, expires_at)` 且不晚于当前时间的 actual_cost，合计所有 API Key。展示与网关调用同一个函数；再次成功购买开启新的用量周期，单纯人工延长有效期不重置周期。不删除历史记录、不清零原生月用量。

由于原生月窗口可以包含多个购买周期，累计分组的日/周/月原生额度限制均须关闭，由外置网关按本次额度校验。所有计费入口必须经过网关。此配置变更不能先于新网关上线，否则可能失去累计额度限制。分组 23、24、25、26 都需要核对，不能复用上一版本只迁移 23/24 的脚本。

## 原页面兼容扩展

自有网关只读代理订阅列表/详情接口，完整转发访问者自己的 Authorization，先由 Sub2API 校验权限，只有成功返回的订阅才能计算用量。响应增加累计模式、总额度、周期信息；原生月展示字段仅在返回值中映射为本周期数据，并将月重置时间设为空，不写回上游。

`quota-gateway/ui/bridge.js` 是独立扩展，仅修改累计套餐行的“每月/Monthly”标签并隐藏倒计时，支持 SPA 重绘。上游 Vue 源码及哈希 JS 包不修改。部署入口通过自有 `install-ui-bridge.mjs` 添加一行扩展引用，自动保留原 index.html 备份；上游前端升级后重新安装引用即可。

部署时将 `deploy/caddy-subscription-presentation.caddy` 路由放在通用 API/静态页规则之前，转发只读订阅接口与 `/quota-ui/*`。生产已完成这些路由、原生累计分组限制及静态入口变更。

## 用户端显示与发布记录

累计套餐显示本周期累计用量和到期提示，隐藏重置按钮；日固定额度套餐保留重置按钮，不添加累计到期提示。扩展限定在各自卡片内处理，禁止向上查找到包含多个套餐的网格。到期提示复用原生重置提示的 `text-xs text-gray-500 dark:text-dark-400` 样式。两类套餐同屏、动态更新及旧错误提示清理已通过回归测试，用户确认卡片显示正确。

订阅接口的分组描述按商品配置生成中文说明，包含标准价格、单次购买有效期、每日或累计额度和对应重置规则；描述只在响应中替换，不修改用户有效期及历史消费。
