# 管理员重置并发与失败补偿修复

日期：2026-10-25，北京时间。

## 修复后的行为

固定日额度套餐的管理员重置先使用调用者 Bearer token 请求内部 Sub2API 的管理员订阅详情接口。
鉴权成功后，将操作持久化到自有表 `zhisales_subscription_resets`。
不再对受管套餐执行“上游清零后再写窗口”的两段变更。

- 管理员、用户端与零点任务共用按订阅划分的 PostgreSQL advisory lock。
- 用量清零、窗口边界及 `applied` 记录在同一个事务中提交；数据库时间在获取锁后捕获，保留微秒精度。
- 事务失败时整体回滚，持久化的 `pending` 操作可由后台恢复。
- 已提交操作只重试缓存失效；不重放清零、窗口更新或用户端有效期扣减。
- 缓存投递使用现有 Redis 计费缓存和订阅 L1 失效频道；没有在线订阅者时保留待恢复记录。
- 每 5 秒重试，启动时立即扫描；领取和确认使用行锁，重复投递保持幂等。
- 零点任务在订阅锁内重新检查是否过期、是否仍需翻页，避免覆盖刚完成的手动重置。
- 累计套餐保留上游原有重置行为。管理员重置不改变有效期或未选择的窗口。

成功返回 `X-Quota-Reset-ID`。待恢复的操作返回 503、`reset_id` 和 `recovery_pending:true`，
提示等待后台恢复，避免重新提交新的重置。操作记录保存上游管理员鉴权请求 ID，不保存 token。

只修改并发布自有 `subscription-reset-service`。未修改开源 Sub2API 源码，未重启 Sub2API、额度控制器或账号池。
